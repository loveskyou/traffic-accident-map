# 전국 교통사고 다발지역 지도 설계

작성일: 2026-09-27
개정: 2026-09-27 (데이터 출처, 연도 체계, 유형별 기간 차이 반영)
상태: 사용자 승인 완료

## 1. 목적과 성공 기준

### 목적
누구나 휴대폰이나 PC로 전국의 교통사고 다발지역을 사고 유형별·연도별로 둘러볼 수 있는 무료 공개 웹사이트를 만든다.

### 사용자가 정한 것
- 여러 사람이 쓰는 공개 서비스다.
- 특정 대상 없이 누구나 전국 지도를 둘러본다.
- 도로교통공단 다발지역 10종을 켜고 끌 수 있는 층으로 올린다.
- 최근 여러 해 데이터를 넣고 연도를 고를 수 있게 한다. 여러 해 연속 다발지역은 따로 표시한다.
- 주소·장소 검색과 시도→시군구 선택을 모두 제공한다.
- 무료로만 운영한다.

### 가정
- 휴대폰 화면을 우선으로 설계한다.
- 첫 버전에는 회원가입, 댓글, 광고가 없다.
- 데이터는 1년 단위로 공개되므로 실시간 갱신은 필요 없다. 1년에 한 번 교체한다.
- 한국어로만 제공한다.

### 성공 기준
1. 휴대폰과 PC에서 전국 지도가 열리고, 10종 유형을 켜고 끌 수 있다.
2. 장소·주소 검색이나 지역 선택으로 원하는 곳으로 이동한다.
3. 다발지역을 누르면 지점 이름, 집계 기간, 발생 건수, 사망·중상·경상자 수, 선정 기준이 나온다.
4. 연도를 2021~2025년 중에서 바꾸면 그 연도 자료로 바뀌고, 1년 단위 유형에서는 여러 해 연속 다발지역이 눈에 띄게 표시된다.
5. 무료 주소로 인터넷에 공개되어 누구나 접속할 수 있다.

## 2. 데이터 출처

### 출처
도로교통공단 교통사고정보개방시스템(https://opendata.koroad.or.kr)의 다발지역 REST API를 쓴다. 이 시스템은 10종 전부를 같은 주소 규칙, 같은 요청 변수, 같은 응답 항목으로 제공하며 인증키 하나로 모두 호출할 수 있다.

공공데이터포털은 10종 중 6종만 직접 제공하고 나머지 4종(보행자, 이륜차, 음주운전, 화물차)은 이 시스템으로 연결만 하므로 쓰지 않는다. 공공데이터포털 목록 기준 10종 모두 이용허락범위 제한이 없다.

### 요청 형식
```
https://opendata.koroad.or.kr/data/rest/frequentzone/<경로>
  ?authKey=<인증키>&searchYearCd=<연도코드>&siDo=<시도코드>&guGun=<시군구코드>
  &type=json&numOfRows=<건수>&pageNo=<페이지>
```

### 응답 형식
```
{ "resultCode": "00", "resultMsg": "NORMAL_CODE", "totalCount": N,
  "items": { "item": [ {afos_fid, afos_id, bjd_cd, spot_cd, sido_sgg_nm, spot_nm,
                        occrrnc_cnt, caslt_cnt, dth_dnv_cnt, se_dnv_cnt, sl_dnv_cnt,
                        wnd_dnv_cnt, lo_crd, la_crd, geom_json}, ... ] } }
```
- 결과 코드: 00 성공, 03 데이터 없음, 10 파라미터 오류, 99 알 수 없는 오류.
- `lo_crd`, `la_crd`는 문자열로 온 경도·위도(EPSG 4326)다.
- `geom_json`은 폴리곤 GeoJSON을 담은 문자열이다.
- 결빙 문서에는 사고건수 항목이 `occrmc_cnt`로 표기되어 있어 두 이름을 모두 받는다.
- `totalCount`의 위치와 결과가 1건일 때 `item`이 목록인지 객체인지는 구현 1단계에서 실제 호출로 확정한다.

### 연도와 연도코드
`searchYearCd`는 연도 숫자가 아니라 유형·연도마다 정해진 7자리 코드다. 교통사고정보개방시스템의 "요청변수 코드 다운로드" 파일(AccidentHazard_CodeList.xlsx)에서 가져온다.

화면의 "연도"는 **기준연도**다. 1년 단위 유형은 그해, 누적 유형은 집계 기간의 마지막 해를 뜻한다. 예: 보행자 "23-25년" 자료의 기준연도는 2025다.

### 시도·시군구 코드
같은 코드 파일의 시도·시군구 시트를 쓴다. 일부 시도 코드가 바뀌었고, 전남광주통합특별시는 시군구 코드도 바뀌었다.

| 현재 시도 | 현재 코드 | 예전 코드 |
|---|---|---|
| 강원특별자치도 | 51 | 42 (강원도), 시군구 코드 같음 |
| 전북특별자치도 | 52 | 45 (전라북도), 시군구 코드 같음 |
| 전남광주통합특별시 | 12 | 29 (광주광역시), 46 (전라남도), 시군구 코드 다름 (예: 광산구 새 330 / 예전 200, 광양시 새 190 / 예전 230) |

전남광주의 예전 시군구 코드는 코드 파일의 "광주광역시(구)", "전라남도(구)" 묶음에서 이름으로 짝을 찾는다. 어느 기준연도부터 새 코드를 쓰는지는 문서마다 다르므로, 수집기는 시군구마다 (시도 코드, 시군구 코드) 후보 목록을 두고 새 코드 짝을 먼저 시도하고 결과가 없으면 예전 짝을 시도한다. 사용한 짝은 원본에 기록한다.

## 3. 방식 결정

**데이터를 미리 받아 정적 파일로 제공한다.** 1년에 한 번 수집 프로그램이 API에서 데이터를 받아 파일로 가공하고, 웹사이트는 그 파일만 읽는다. 방문자의 브라우저는 교통사고정보개방시스템을 직접 호출하지 않는다.

선택 이유:
- 방문자 수와 관계없이 API 호출 한도에 걸리지 않는다.
- 인증키가 웹사이트에 드러나지 않는다.
- 브라우저 차단(CORS) 문제가 없다.
- 서버가 없어 무료이고 관리할 곳이 적다.

검토 후 버린 방식:
- 방문 시마다 중간 서버가 API를 호출하는 방식. 데이터가 연 1회 갱신이라 이점이 없고, 방문자가 늘면 한도를 초과하며 관리 부담이 크다.
- 지도를 브이월드로 쓰는 방식. 장소 검색 품질이 카카오보다 낮다. 대신 지도 모듈을 분리해 나중에 교체할 수 있게 한다.

## 4. 전체 구조

```
[내 컴퓨터, 연 1회]
  수집기 ──▶ 교통사고정보개방시스템 다발지역 API 10종
    │  원본 저장 (raw/)
    ▼
  가공기
    │  지도용 파일 생성, 연속 다발지역 계산 (site/data/)
    ▼
[GitHub Pages, 무료]
  웹사이트 ──▶ 카카오맵 (지도 표시, 장소 검색, 지역명 좌표 변환)
```

| 구성 요소 | 하는 일 | 쓰는 것 |
|---|---|---|
| 유형 목록 | 10종의 경로, 기간, 반경, 색, 기준 문장, 연도코드 | 파이썬 |
| 지역 목록 | 코드 파일에서 시군구와 (시도, 시군구) 코드 후보를 만든다 | 파이썬, openpyxl |
| API 호출기 | 한 조합의 모든 페이지를 받고 결과 코드를 판별한다 | 파이썬 표준 라이브러리 |
| 수집기 | 유형 × 연도 × 시군구 조합을 받아 원본 저장. 이어받기 | 파이썬 |
| 연속 계산기 | 1년 단위 유형에서 같은 장소의 연속 연수를 계산한다 | 파이썬 |
| 가공기 | 원본을 지도용 파일로 바꾼다 | 파이썬 |
| 웹사이트 | 파일을 읽어 지도에 표시한다 | HTML, 자바스크립트 모듈, 카카오맵 |

웹사이트 내부 역할:
- 지도 담당: 카카오맵과 통신하는 코드만 모은다. 브이월드로 교체할 때 이 부분만 바꾼다.
- 계산 담당: 거르기, 기간 문구, 정보 창 문구 같은 화면과 무관한 계산. 자동 시험 대상.
- 데이터 담당: 파일 읽기와 캐시.
- 화면 담당: 유형 버튼, 연도, 연속 필터, 검색, 지역 선택, 정보 창.

별도 개발 도구(빌드 과정, 프레임워크)는 쓰지 않는다.

## 5. 데이터 수집

### 순서
1. **탐색 호출.** 서울 강남구로 10종 × 기준연도 2021·2025를 호출해 요청 변수 이름, 응답 모양, 결과가 1건일 때 모양, `totalCount` 위치를 확정한다. 강원 원주시, 전북 전주시완산구, 광주 광산구, 전남 목포시로 새 코드와 예전 코드를 각각 호출해 코드 전환 시점을 확인한다. 하루 호출 한도가 있는지 응답과 사이트 안내로 확인한다.
2. **본 수집.** 유형, 기준연도, 시군구 조합마다:
   - 이미 받은 조합이면 건너뛴다.
   - (시도, 시군구) 코드 후보를 차례로 시도한다. 결과가 있는 첫 짝을 쓴다. 모든 후보가 "데이터 없음"이면 빈 결과로 기록한다.
   - 결과가 여러 페이지면 끝까지 받는다.
   - 원본과 사용한 시도 코드를 저장하고 진행 기록에 남긴다.
   - 한도 초과로 판단되면 멈추고 다음 날 이어서 실행하라고 안내한다.
   - 그 밖의 오류는 기록하고 다음 조합으로 넘어간다. 오류 난 조합은 다음 실행 때 다시 시도한다.

### 호출량
시군구 270곳 × 10종 × 5년이면 13,500회이고, 코드 후보가 둘 이상인 지역에서 호출이 조금 늘어난다. 호출 사이에 0.1초를 쉰다.

### 인증키 관리
교통사고정보개방시스템 인증키는 프로젝트 폴더의 `config.local.json`에 저장하고 git에 올리지 않는다. 사용자가 직접 입력한다. 오류 메시지와 기록에는 인증키가 들어간 주소를 출력하지 않는다.

## 6. 저장 형식

```
pipeline/data/AccidentHazard_CodeList.xlsx   요청변수 코드 파일
raw/                                         원본. git에 올리지 않는다
  <유형>/<기준연도>/<시도코드>-<시군구코드>.json   {"code_used": [11, 680], "items": [...]}
  progress.json                              완료 조합 기록
site/data/                                   웹사이트가 읽는 가공 파일
  meta.json                                  갱신일, 연도 목록
  types.json                                 유형 10종의 공개 정보
  regions.json                               시도별 시군구 이름 목록
  <기준연도>/<유형>.json                      전국 다발지역 점 목록
  <기준연도>/<유형>/<시도코드>.json            시도별 구역 모양 {점id: 좌표}
```

### 점 한 건
```
{"id": "lg-2025-6967684", "n": 지점명, "r": 시도시군구명, "lat": 위도, "lng": 경도,
 "sd": 시도코드, "c": 사고, "k": 사상자, "d": 사망, "s": 중상, "l": 경상, "w": 부상신고,
 "streak": 연속연수, "since": 연속시작연도}
```
`streak`, `since`는 1년 단위 유형에만 있다.

### 파일 분할
구역 모양은 점보다 훨씬 크므로 항상 시도별로 나누어, 동네 단위로 확대했을 때 화면에 보이는 시도의 파일만 읽는다. 점 목록은 전국 한 파일로 둔다. 가공 후 가장 큰 점 파일 크기를 기록하고, 휴대폰에서 첫 화면이 3초 안에 뜨는지 확인한다.

### 연속 다발지역 판단 규칙
1년 단위 유형(일반, 보행어린이, 자전거, 어린이보호구역)에만 적용한다. 기준연도 오름차순으로, 각 다발지역을 이전 연도까지 알려진 장소 중 그 유형의 반경 안에 있는 가장 가까운 장소에 연결한다. 연결된 장소가 바로 전해에도 나왔으면 연속 연수를 1 늘리고, 아니면 1부터 다시 센다. 누적 유형은 기간이 겹쳐 연속이 당연하므로 적용하지 않는다.

## 7. 화면

### 휴대폰 배치
```
┌─────────────────────────┐
│ 장소·주소 검색      [지역] │
├─────────────────────────┤
│ 연도 선택  ☐ 연속 다발만 보기 │
├─────────────────────────┤
│         카카오 지도        │
├─────────────────────────┤
│ [일반][보행자][어린이]…   ▲ │  유형 버튼, 위로 올리면 전체 목록과 기준
```

PC(가로 900px 이상)에서는 같은 요소를 왼쪽 패널에 세로로 배치하고 지도를 넓게 쓴다.

### 동작
- **처음 화면.** 전국 지도에 기준연도 2025년의 일반 다발지역이 켜진 상태로 연다.
- **유형 표시.** 유형마다 다른 색 원을 쓴다. 연속 2년 이상인 점은 굵은 테두리로 표시한다. 누른 자리 30m 안에 다른 점이 있으면 그 점들을 목록으로 보여 주고 고르게 한다.
- **축척에 따른 표시.** 멀리서 볼 때는 가까운 점을 숫자 원으로 묶는다. 동네 단위(카카오맵 확대 단계 5 이하)로 확대하면 화면 안 다발지역의 구역 모양을 반투명하게 칠한다.
- **연속 다발만 보기.** 켜면 연속 2년 이상인 점만 남는다. 누적 유형 점은 이때 숨는다.
- **정보 창.** 지점명, 유형, 집계 기간(예: "2023~2025년 3년간"), 연속 여부와 기간, 사고·사망·중상·경상·부상신고 수, 해당 유형 선정 기준, 카카오맵으로 보기 링크.
- **장소 검색.** 카카오 장소 검색 결과 목록에서 고르면 그곳으로 이동해 확대한다.
- **지역 선택.** 시도를 고르고 시군구를 고르면 카카오 주소 검색으로 좌표를 얻어 그 지역으로 이동한다.
- **안내 문구.** "자료: 도로교통공단 교통사고정보개방시스템", 마지막 갱신일, "과거 통계이며 현재 도로 상황과 다를 수 있습니다"를 항상 표시한다.

### 카카오맵 키
카카오 개발자 앱의 JavaScript 키를 쓴다. 이 키는 등록한 사이트 주소에서만 작동하므로 웹사이트 파일에 넣어도 된다. 개발용 `http://localhost:8000`과 공개 사이트 주소를 등록한다. 2026년 7월 정책상 개발자 계정의 첫 번째 활성 앱에 무료 한도가 적용된다.

## 8. 오류 처리

| 상황 | 처리 |
|---|---|
| 수집 중 한도 초과 | 멈추고 다음 날 이어서 실행하라고 안내. 진행 기록으로 이어받기 |
| HTTP 성공인데 결과 코드가 오류 | 결과 코드로 판별해 오류로 처리하고 해당 조합을 미완료로 남김 |
| 결과 코드 03 데이터 없음 | 정상 빈 결과. 코드 후보가 남아 있으면 다음 후보 시도 |
| JSON이 아닌 응답 | 오류로 처리. 응답 앞부분 200자만 기록 |
| 좌표가 비었거나 한국 범위(위도 33.0~38.7, 경도 124.5~132.0) 밖 | 지도에 올리지 않고 가공 보고서에 개수 기록 |
| 구역 모양이 비었거나 깨짐 | 점은 올리고 구역 모양만 생략 |
| 카카오맵 로드 실패 | "지도를 불러오지 못했습니다. 잠시 후 다시 시도하세요" 표시 |
| 장소 검색 결과 없음 | "검색 결과가 없습니다. 지역 버튼으로 찾아보세요" 표시 |
| 데이터 파일 로드 실패 | 해당 유형 버튼에 오류 표시, 다른 유형은 계속 동작 |
| 지점명에 HTML 특수문자 | 화면에 넣기 전에 모두 이스케이프 |

## 9. 검증

실행과 확인은 모두 AI가 수행하고 사용자에게는 결과만 보고한다.

1. **파이썬 자동 시험(pytest).** 유형 목록, 지역 목록, API 응답 판별, 페이지 넘김, 코드 후보 전환, 이어받기, 한도 초과 중단, 연속 계산, 가공 결과를 가짜 응답과 예시 데이터로 시험한다.
2. **자바스크립트 자동 시험(node --test).** 거르기, 기간 문구, 정보 창 문구, 이스케이프, 근처 점 찾기를 시험한다.
3. **실제 API 확인.** 탐색 호출 결과를 보고서로 남긴다.
4. **브라우저 확인.** 유형 켜기·끄기, 연도 변경, 연속 필터, 검색, 지역 선택, 정보 창, 겹친 점 목록을 PC와 휴대폰 크기(390×844)에서 직접 조작해 확인한다.
5. **숫자 대조.** 지도에 표시된 다발지역 세 곳의 수치를 원본 파일과 대조한다.
