# 전국 교통사고 다발지역 지도 설계

작성일: 2026-09-27
상태: 사용자 검토 대기

## 1. 목적과 성공 기준

### 목적
누구나 휴대폰이나 PC로 전국의 교통사고 다발지역을 사고 유형별·연도별로 둘러볼 수 있는 무료 공개 웹사이트를 만든다.

### 사용자가 정한 것
- 여러 사람이 쓰는 공개 서비스다.
- 특정 대상 없이 누구나 전국 지도를 둘러본다.
- 도로교통공단 다발지역 10종을 켜고 끌 수 있는 층으로 올린다.
- 최근 여러 해 데이터를 넣고 연도를 고를 수 있게 한다. 여러 해 연속 다발지역은 따로 표시한다.
- 주소·장소 검색과 시도→시군구 선택을 모두 제공한다.
- 무료로만 운영한다.

### 가정
- 휴대폰 화면을 우선으로 설계한다.
- 첫 버전에는 회원가입, 댓글, 광고가 없다.
- 데이터는 1년 단위 통계이므로 실시간 갱신은 필요 없다. 1년에 한 번 교체한다.
- 한국어로만 제공한다.

### 성공 기준
1. 휴대폰과 PC에서 전국 지도가 열리고, 10종 유형을 켜고 끌 수 있다.
2. 장소·주소 검색이나 지역 선택으로 원하는 곳으로 이동한다.
3. 다발지역을 누르면 지점 이름, 발생 건수, 사망·중상·경상자 수가 나온다.
4. 연도를 바꾸면 그 해의 다발지역으로 바뀌고, 연속 다발지역이 눈에 띄게 표시된다.
5. 무료 주소로 인터넷에 공개되어 누구나 접속할 수 있다.

### 일반 다발지역 API에서 확인한 사실
- 요청 조건: 연도, 시도 코드 2자리, 시군구 코드 3자리가 필수다.
- 응답 항목: 지점명, 위도, 경도, 다발지역 폴리곤(GeoJSON), 발생건수, 사상자수, 사망자수, 중상자수, 경상자수, 법정동코드, 시도시군구명, 다발지역ID.
- 형식: JSON, XML.
- 개발계정 하루 10,000회. 자동승인. 무료. 이용허락범위 제한 없음.
- 다발지역 기준: 반경 150m 안에서 연 3건 이상.

### 아직 확인하지 않은 사실
- 각 API가 제공하는 연도 범위.
- 나머지 9종의 요청 조건, 응답 항목, 다발지역 기준, 이용허락범위가 일반 API와 같은지 여부.

이 사실들은 구현 1단계의 탐색 호출로 확인하고, 결과에 따라 수집 연도와 화면 설명을 확정한다.

## 3. 방식 결정

**데이터를 미리 받아 정적 파일로 제공한다.** 1년에 한 번 수집 프로그램이 공공 API에서 데이터를 받아 파일로 가공하고, 웹사이트는 그 파일만 읽는다. 방문자의 브라우저는 공공 API를 직접 호출하지 않는다.

선택 이유:
- 방문자 수와 관계없이 공공 API 하루 한도에 걸리지 않는다.
- 공공데이터 인증키가 웹사이트에 드러나지 않는다.
- 브라우저 차단(CORS) 문제가 없다.
- 서버가 없어 무료이고 관리할 곳이 적다.

검토 후 버린 방식:
- 방문 시마다 중간 서버가 공공 API를 호출하는 방식. 데이터가 연 1회 갱신이라 이점이 없고, 방문자가 늘면 한도를 초과하며 관리 부담이 크다.
- 지도를 브이월드로 쓰는 방식. 장소 검색 품질이 카카오보다 낮다. 대신 지도 모듈을 분리해 나중에 교체할 수 있게 한다.

## 4. 전체 구조

```
[내 컴퓨터, 연 1회]
  수집기 ──▶ 공공데이터포털 다발지역 API 10종
    │  원본 저장 (raw/)
    ▼
  가공기
    │  지도용 파일 생성, 연속 다발지역 계산 (site/data/)
    ▼
[GitHub Pages, 무료]
  웹사이트 ──▶ 카카오맵 (지도 표시, 장소 검색)
```

### 구성 요소

| 구성 요소 | 하는 일 | 쓰는 것 |
|---|---|---|
| 지역 코드표 생성 | 법정동 코드 목록에서 전국 시도·시군구 코드와 이름, 중심 좌표를 만든다 | 파이썬 |
| 수집기 | 유형 × 연도 × 시군구 조합으로 API를 호출해 원본을 저장한다. 이어받기 지원 | 파이썬 |
| 가공기 | 원본을 지도용 파일로 바꾸고 연속 다발지역을 계산한다 | 파이썬 |
| 웹사이트 | 파일을 읽어 지도에 표시한다 | HTML, 자바스크립트, 카카오맵 |

웹사이트 내부 역할:
- 지도 담당: 카카오맵과 통신하는 코드만 모은다. 브이월드로 교체할 때 이 부분만 바꾼다.
- 층 담당: 유형 10종 켜기·끄기.
- 연도 담당: 연도 선택, 연속 다발지역 강조와 필터.
- 찾기 담당: 장소 검색, 시도→시군구 선택.
- 상세 담당: 다발지역 정보 창.

별도 개발 도구(빌드 과정, 프레임워크)는 쓰지 않는다. 사용자가 코드를 직접 고치지 않고 AI에게 수정을 맡기므로 구조가 단순해야 한다.

## 5. 데이터 수집

### 순서
1. **탐색 호출.** 10종 API를 서울 한 구에 대해 한 번씩 호출해 연도 범위, 요청 조건, 응답 모양을 확인한다. 결과로 수집 연도를 확정한다.
2. **본 수집.** 유형, 연도, 시군구 조합마다:
   - 이미 받은 조합이면 건너뛴다.
   - API를 호출하고, 결과가 여러 페이지면 끝까지 받는다.
   - 원본을 저장하고 진행 기록에 "완료"로 남긴다.
   - 하루 한도 초과 응답을 받으면 멈추고 다음 날 이어서 실행하라고 안내한다.

### 호출량
시군구 약 250개 × 10종 × 5년이면 약 12,500회다. 개발계정 하루 한도가 API마다 10,000회이므로, 한도는 API별로 따로 계산된다면 하루에 끝날 수 있고 그렇지 않더라도 이틀이면 끝난다. 이어받기 기능으로 처리한다.

### 인증키 관리
공공데이터포털 인증키는 프로젝트 폴더의 설정 파일에 저장하고, 이 파일은 git에 올리지 않는다. 사용자가 직접 키를 입력한다.

## 6. 저장 형식

```
raw/                          원본 보관. 인터넷에 올리지 않는다
  <유형>/<연도>/<시도시군구코드>.json
  progress.json               수집 진행 기록

site/                         GitHub Pages에 올리는 웹사이트
  data/
    regions.json              시도·시군구 목록, 이름, 중심 좌표
    types.json                유형 10종의 이름, 색, 다발지역 기준 설명, 제공 연도
    <연도>/<유형>.json          전국 다발지역 점 목록
    <연도>/<유형>/<시도코드>.json 시도별 다발지역 구역 모양
    places.json               연속 다발지역 계산 결과
```

### 다발지역 한 건에 남기는 정보
지점명, 위도, 경도, 구역 모양, 발생건수, 사상자수, 사망자수, 중상자수, 경상자수, 시도시군구명, 유형, 연도.

### 파일 분할
전국 점 파일은 멀리서 볼 때 쓰고, 구역 모양 파일은 확대했을 때 해당 시도만 읽는다. 가공 후 실제 파일 크기를 재서, 전국 파일이 충분히 작으면 분할하지 않고 하나로 합친다. 판단 기준은 휴대폰에서 첫 화면이 3초 안에 뜨는지로 한다.

### 연속 다발지역 판단 규칙
같은 유형에서 서로 다른 연도의 다발지역 중심점이 100m 안에 있으면 같은 장소로 본다. 같은 장소가 연속된 연도에 몇 번 나타났는지 세어 "N년 연속"으로 표시한다. 실제 데이터로 묶인 결과를 확인하고 필요하면 거리를 조정한다.

## 7. 화면

### 휴대폰 배치
```
┌─────────────────────────┐
│ 장소·주소 검색      [지역] │
├─────────────────────────┤
│ 연도 선택  ☐ 연속 다발만 보기 │
├─────────────────────────┤
│                         │
│         카카오 지도        │
│                         │
├─────────────────────────┤
│ [일반][보행자][어린이]…   ▲ │  유형 버튼, 위로 올리면 전체 목록과 설명
└─────────────────────────┘
```
PC에서는 같은 요소를 왼쪽 패널에 세로로 배치하고 지도를 넓게 쓴다.

### 동작
- **처음 화면.** 전국 지도에 최신 연도의 일반 다발지역이 켜진 상태로 연다.
- **유형 표시.** 유형마다 다른 색을 쓴다. 여러 유형이 겹친 자리를 누르면 그 자리의 유형을 모두 목록으로 보여 준다.
- **축척에 따른 표시.** 멀리서 볼 때는 가까운 점을 숫자 원으로 묶는다. 동네 단위로 확대하면 구역 모양을 반투명하게 칠한다.
- **정보 창.** 지점명, 유형, 연도, 연속 다발 여부와 기간, 발생·사망·중상·경상 수, 해당 유형의 다발지역 기준, 카카오맵으로 보기 링크.
- **장소 검색.** 카카오 장소 검색 결과를 고르면 그곳으로 이동해 확대한다.
- **지역 선택.** 시도를 고르고 시군구를 고르면 그 지역으로 이동한다.
- **안내 문구.** "자료: 도로교통공단", 마지막 갱신일, "과거 통계이며 현재 도로 상황과 다를 수 있습니다"를 항상 표시한다.

### 카카오맵 키
카카오 개발자 앱의 JavaScript 키를 쓴다. 공개 사이트 주소를 등록해 그 주소에서만 키가 작동하게 한다. 2026년 7월 정책상 개발자 계정의 첫 번째 활성 앱에 무료 한도가 적용된다. 정확한 무료 한도는 앱 등록 시 확인한다.

## 8. 오류 처리

| 상황 | 처리 |
|---|---|
| 수집 중 하루 한도 초과 | 멈추고 다음 날 이어서 실행하라고 안내. 진행 기록으로 이어받기 |
| HTTP 성공인데 본문이 에러 | 본문의 결과 코드를 확인해 에러로 처리하고 해당 조합을 미완료로 남김 |
| 해당 지역에 다발지역 없음 | 정상 결과로 기록. 빈 결과와 에러를 구분 |
| 특정 유형이 특정 연도를 제공하지 않음 | types.json의 제공 연도에서 제외하고 화면에서 선택할 수 없게 함 |
| 좌표가 비었거나 한국 범위를 벗어남 | 지도에 올리지 않고 가공 보고서에 개수 기록 |
| 카카오맵 로드 실패 | "지도를 불러오지 못했습니다. 잠시 후 다시 시도하세요" 표시 |
| 장소 검색 결과 없음 | "검색 결과가 없습니다. 지역 버튼으로 찾아보세요" 표시 |
| 데이터 파일 로드 실패 | 해당 유형 버튼에 오류 표시, 다른 유형은 계속 동작 |

## 9. 검증

실행과 확인은 모두 AI가 수행하고 사용자에게는 결과만 보고한다.

1. **수집기.** 실제 API로 서울 한 구를 받아 원본 저장을 확인한다. 한도 초과와 "성공인데 에러" 응답은 가짜 응답으로 시험한다. 이어받기가 완료 조합을 건너뛰는지 시험한다.
2. **가공기.** 작은 예시 데이터로 출력 파일 형식과 연속 다발지역 묶음 규칙을 시험한다.
3. **웹사이트.** 브라우저에서 유형 켜기·끄기, 연도 변경, 연속 다발 필터, 검색, 지역 선택, 정보 창을 직접 조작해 확인한다. 휴대폰 크기 화면에서도 확인한다.
4. **숫자 대조.** 지도에 표시된 다발지역 몇 곳의 수치를 원본 파일과 대조한다.
